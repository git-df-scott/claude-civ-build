# CivAgentBridge — Project Retrospective

Written 2026-07-17, after two days of building and one evening of autonomous play.
Audience: future sessions (and Duncan). Companion to the `civ6-bridge` memory file,
which holds the operational recipes; this is the honest assessment.

## Where things stand

A Claude Code session can start Civ 6, load or create a game, read full game
state every turn, and play — found cities, move and fight units, set research,
civics, and production, end turns — with no human at the keyboard. The win
campaign reached **turn 174 as Kongo** (2 cities, Library/Market/Water Mill/two
Campuses, ~1800 gold) before the session was closed mid-batch.

## What went well

- **Verify-before-build held up.** The two spec questions (does `io` work in the
  sandbox? which turn events fire?) were answered in-engine before the
  architecture was committed. Both answers contradicted the naive design
  (io is nil; most turn events never fire) and would have sunk a guessed build.
- **Evidence-standard testing.** Every action was proven by before/after state
  change — scout actually at (25,24), city count actually 2, barb damage
  actually 32→61 — never by "command returned ok". This caught two actions that
  *acked* fine but did nothing (melee without the ATTACK modifier; found_city on
  a city tile).
- **The transport mystery was solved by instrumentation, not theories.** After
  several failed guesses, logging every raw tuner frame (tuner_frames.log)
  showed the game stops *reading* the socket after a save load. That evidence
  led to the mid-load-transition reconnect trick, which is now a one-line
  `/reconnect` call and works every time.
- **Root-causing over retrying.** The "11 hours, no progress" first night came
  down to one fact nobody had checked: the game's live user directory is
  `%LOCALAPPDATA%\Firaxis Games\...`, not `Documents\My Games`. Finding that
  took ten minutes of log reading and unblocked everything.
- **Memory discipline paid off across resets.** Context was summarized several
  times mid-project; the memory file's recipes (load-save Lua, context split,
  reconnect timing) let each new context resume in minutes.
- **Batch-play architecture.** Policy queues + a dumb executor + review
  checkpoints between batches is the right shape: the session makes strategy
  decisions at checkpoints, the script grinds turns, and every policy bug found
  became a one-edit fix.

## What could be improved

- **Too many blind retries during the transport saga.** Ten game restarts, and
  several were spent re-testing variants of a theory the evidence already
  contradicted. The frame logger should have been the *first* move after the
  second failure, not the seventh. Lesson: when a black-box protocol misbehaves,
  capture the wire before hypothesizing.
- **The FinishIdle/movement bug cost ~100 game turns.** Units "moved" (ok=true)
  but stayed put for five batches because FinishIdle zeroed their moves seconds
  after the order was issued. The tell was in plain sight — identical unit
  positions in consecutive batch reports — and I didn't compare positions until
  batch 6. Automated regression checks on the state dump (did anything actually
  change?) would have caught it in one batch.
- **Trusting `ok` responses.** Three separate bugs (found_city, melee attack,
  movement) shared one shape: request accepted ≠ effect happened. The bridge
  should verify effects, and now mostly does, but `purchase` still fails with
  `CanStartCommand=false` for unknown reasons — unresolved, ~1800 gold wasted.
- **Duplicate daemons.** Twice I started a second bridge_daemon on port 8321
  without killing the first, and the round-robin between a live and a dead
  instance produced confusing symptoms. The daemon should take a lockfile.
- **Turn pacing is slow.** ~60–90s per turn wall time (AI round + conservative
  sleeps). A full game is 300+ turns ≈ 6+ hours. Tightening the waits and
  detecting turn-start via the auto state dump (instead of polling) could halve it.
- **Policy is still shallow.** No builder improvements, no district placement
  choice, no promotions, no war logic beyond skirmish, settle targets are blind
  offsets with no terrain knowledge. Rivals out-expanded us 6 cities to 2. To
  actually *win*, the state dump needs terrain/yield data and the policy needs
  real settle-site scoring.

## Open items (ranked)

1. Fix `purchase` (get FailureReasons from CanStartCommand's results table).
2. Settle-site quality: dump nearby tile yields/fresh-water so targets aren't blind.
3. Faster turn loop (event-driven on BRIDGE_STATE, tighter sleeps).
4. Builder actions (BUILD_IMPROVEMENT) — builders currently idle.
5. Ranged/city attack live test (implemented, never exercised).
6. Daemon lockfile + auto-restart watchdog for true unattended runs.
